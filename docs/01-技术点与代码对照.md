# 技术点 → 代码 → 怎么讲

> 这份文档的用途：面试前过一遍，确保每个技术点都能**指到一行代码**，并且能说出"为什么这么做"。

---

## 1. 适配器模式（对应简历：Workflow 适配器）

**代码位置**
- `adapter/AiProviderAdapter.java` — 适配器接口
- `adapter/OpenAiCompatibleAdapter.java` — OpenAI 兼容协议实现
- `adapter/MockAdapter.java` — 无 key 兜底
- `adapter/AdapterRegistry.java` — 按 model 前缀查表

**怎么讲**
> 「上层只依赖 `ChatRequest` / `ChatChunk` 这一套统一结构。每个厂商自己负责把自己的协议翻译成这套结构：OpenAI 是 `choices[0].delta.content`，思维链是 `reasoning_content`，有些厂商是 `result`。新增一个厂商 = 新增一个实现类，注册表不用改，上层也不用改。」

**追问准备**
- 和策略模式的区别？→ 适配器解决"接口不兼容"，策略解决"算法可替换"；这里两者都用到了（适配 + 按 model 选实现）。
- 为什么用注册表而不是 if-else？→ 开放封闭：加厂商不改已有代码，也方便按配置灰度。

## 2. 循环节点（对应简历：Workflow 循环节点）

**代码位置**
- `workflow/LoopNode.java`
- `workflow/LoopNodeTest.java`

**怎么讲**
> 「循环变量每轮结束写回，下一轮通过它读上一轮的结果；终止条件在**轮末**求值，所以能引用本轮产出；外面还有 `maxCount` 兜底 —— 条件是用户配的，可能永远不成立，没有上限就是死循环。」

**追问准备**
- 为什么上限要有范围校验？→ `(0, 100]`，配置错误直接拒绝启动/构建节点，而不是运行时才炸。
- 和迭代（Iteration）的区别？→ 迭代是遍历数组、子图嵌套；循环是控制流重复，结构扁平，靠起止标记界定循环体。
- 中途取消怎么停？→ 状态位 + 每轮开始前检查（本项目未实现，属于下一步）。

## 3. SSE 流式链路（对应简历：ChatBox 流式链路）

**代码位置**
- `chat/stream/SseFrameParser.java` — 帧切分
- `chat/stream/ChunkNormalizer.java` — 多厂商归一
- `chat/ChatController.java` — `SseEmitter` 推送
- `static/index.html` — 浏览器端 `EventSource` 演示

**怎么讲**
> 「HTTP 的传输分片不等于事件边界：一次 read 可能拿到半个事件，也可能拿到两个半。所以必须自己攒 buffer，按空行切帧，再把 `data:` 字段拼出来。粘包和半包都在 `SseFrameParserTest` 里覆盖了。」

**追问准备**
- 为什么不用 WebSocket？→ 单向推送够用、复用 HTTP 鉴权与网关、不用维护心跳。
- 为什么不用 `EventSource`？→ 它只支持 GET、不能带自定义 Header；真实场景需要 POST + `Authorization`。
- 多厂商差异怎么处理？→ `ChunkNormalizer` 把 `delta` / `result` / `reasoning_content` 统一成 `ChatChunk`。

## 4. RabbitMQ（对应简历：玉米项目异步化 + 技能栏"可靠性/幂等"）

**代码位置**
- `mq/RabbitTaskDispatcher.java` — 生产端
- `mq/TaskConsumer.java` — 消费端（手动 ack）
- `mq/ProcessedTask.java` — 去重表（唯一约束）
- `mq/RabbitConfig.java` — 交换机/队列/持久化

**怎么讲**
> 「可靠性是三个点连起来：生产端消息持久化、队列持久化、消费端手动 ack。重复投递靠 `processed_task` 的**唯一约束**挡，而不是"先查再插"—— 那个在并发下会漏。」

**追问准备**
- 消费失败怎么办？→ 代码里 `basicNack(requeue=false)`，避免毒消息打爆队列；生产上配死信队列兜底。
- 为什么要幂等？→ at-least-once 语义下重复投递是常态。
- MQ 挂了怎么办？→ 本项目 `app.mq.enabled=false` 时自动降级为同步执行，接口语义不变。

## 5. 多线程与锁（对应简历：发布链路的乐观锁 + 抢占）

**代码位置**
- `publish/PublishRepository.java#casStatus` — 条件更新
- `publish/PublishService.java#claim` / `race` — 抢占与并发演示（`race` 会先把记录复位成 SCHEDULED，方便反复跑）
- `publish/PublishScheduler.java` — 定时扫描
- `config/ExecutorConfig.java` — 线程池参数

**怎么讲**
> 「状态迁移不是先查再改，而是 `UPDATE ... SET status=新值 WHERE id=? AND status=旧值`。返回 0 就说明别人已经推进了，直接返回。`/race` 接口用 20 个线程抢同一条记录，正确结果是只成功 1 个 —— 这是我验证乐观锁的方式。」

**追问准备**
- 乐观锁 vs 悲观锁？→ 冲突少用乐观锁（无阻塞），冲突多用悲观锁/分布式锁。
- ABA？→ 状态单向推进不回退，不存在 ABA；若状态可回退则要版本号。
- 冲突率高会不会打爆 DB？→ 会。要配合前端防抖 + 冲突直接返回而不是无脑重试。
- 线程池为什么 `CallerRunsPolicy`？→ 队列满时回退到调用线程，形成背压，避免静默丢任务。

## 6. 密钥加密（对应简历：Skills 的 AK 权限）

**代码位置**
- `security/AesGcmCipher.java` — AES-GCM 加解密 + 脱敏
- `security/KeyVaultService.java` — 写入加密 / 列表脱敏 / **归属校验**
- `security/ApiKeyController.java` — 越权演示接口

**怎么讲**
> 「明文不落库，只在用的时候解密；列表返回脱敏串；读取时强制带 ownerId，别人的 key 直接 403。**前端过滤不算权限控制** —— 那只是"不显示"，改个参数就拿到了。」

**追问准备**
- 为什么 GCM 不是 CBC？→ GCM 自带完整性校验（tag），能发现密文被篡改。
- 密钥本身怎么管？→ 演示放配置；生产应放 KMS / 环境变量，不能进代码库。
- 为什么用唯一约束去重而不是先查后插？→ 并发下"先查后插"有竞态。

## 7. 构建与发布（对应简历：Skills 构建与发布 15min → 3-5min）

**代码位置**
- `Dockerfile` — 分层顺序 + 多阶段
- `deploy/nginx.conf` — `try_files` 回退 + SSE 关缓冲
- `.github/workflows/ci.yml` — CI 构建与测试

**怎么讲**
> 「原来 `COPY . .` 在 `mvn dependency` 之前，改一行代码就让依赖层全部失效，每次都要重新拉依赖。改成先 `COPY pom.xml` 再 `COPY src`，依赖层就稳定命中缓存。再叠加多阶段构建，最终镜像只有 jar 和 JRE。」

**追问准备**
- 前端刷新 404 的根因？→ history 路由请求真实路径，Nginx 找不到文件；`try_files $uri $uri/ /index.html` 回落。
- SSE 反代要注意什么？→ `proxy_buffering off`，否则增量被 Nginx 攒着一起发，前端看起来"卡住然后一次性出来"。

## 8. 和"真实项目"的差异（边界，别吹）

| 真实项目 | 这个复刻项目 |
|---|---|
| XXL-Job 定时调度 | `@Scheduled`，只复刻"扫描 + 抢占"这一层 |
| 灰度切流由调度服务执行 | 只记录 `grayPercent`，不真的切流 |
| 工作流执行引擎（DAG 调度、并行分支） | 只做线性节点 + 循环节点 |
| 多租户、审计、权限体系 | 只做密钥归属校验 |
| 生产级 RabbitMQ 集群 + 死信 | 单机 + 手动 ack |

**面试时主动说这张表的右列** —— 承认边界比假装完整可信得多。
